# Windows 智能切图与全自动识题验收清单

当前发布的是无模型、无 OCR 的“智能切图”：本机分析版面，用户复核后只把题目或答案切图
放回素材牌库，不创建题卡，也不自动匹配。带 OCR、题答理解、匹配、自动建卡和导出的
“全自动识题”仍未开放，且当前不提供 small / medium 模型下载。

## 2026-07-26 智能切图基线

- 产品 worker 已切换为内置 Rust 视觉切图引擎，无需模型、Python、OpenCV DLL 或网络。
- 切图继承源素材的题目/答案角色；应用后只新增加密派生资产和未分配素材，草稿与题卡数量不变。
- 真实样本覆盖 6 张图片以及新增 18 份 PDF 的首屏渲染页。首轮发现答案解析页过度碎切后，
  增加“行组→题块”两级空白合并；复杂页面仍必须人工复核，不把视觉分块冒充题号识别。
- 设置页和采集工作台分别显示“智能切图（已开放）”与“全自动识题（未开放）”；未来模型档位
  将依据硬件重新设计，当前没有下载或运行入口。

## 2026-07-25 OCR 试验基线（历史证据，未发布）

- 前端：56 个测试文件、278 个测试全部通过；lint、typecheck、生产构建通过。
- Rust：全目标测试通过；识别专项 20 个默认用例覆盖受控 worker、损坏密文隔离、取消/退出/批次删除、整批重启重放、运行时失败快速终止、应用、单页超过 10 题、三阶段故障注入、过期隔离、安全撤销与冲突保护。
- 类型绑定：连续生成 SHA-256 一致。
- Windows：Tauri release 与 NSIS 安装包构建成功。
- 候选运行时：默认关闭的 `local-ocr-runtime` 特性在 Windows/MSVC 下编译通过，并用已校验的
  PP-OCRv6 small 模型与 CPU ONNX Runtime 离线处理本轮 6 张真实试卷页。人工标注共 37 题：
  5 张可读页按 `10、4、3、4、12` 拆出 `33/33` 个区域；1 张严重模糊、水印和手写覆盖页触发
  低可信整页保留而没有冒险切断内容。该 6 图开发结果为 33/37（89.19%）题目起始召回，
  不计作 60/300 张发布准确率门禁。
- 真实落库闭环：双栏 12 题页通过当时的试验 worker、加密源图、建议接受和原子应用生成 12 道
  可恢复草稿；该行为现已被“只写素材牌库”替换。测试同时发现并修复了两处
  旧的 10 题上限：worker 建议容量和 `asset_derivations.position` 数据库约束。
- 数据库升级到 schema v15；v14→v15 测试确认已有派生记录逐行保留，新约束支持位置
  `0..149`，同时拒绝超出 150 张批次容量的位置。
- 产品 worker 接线：应用启动改为统一的门禁工厂；真实样本证据、运行时发布和编译特性必须同时通过，
  否则保持不可用引擎且不读取模型或加载 DLL。通过后也只在用户首次启动识别任务时懒加载运行时，
  并保留一个逻辑处理器、最多使用 4 个推理线程，避免拖慢启动和桌面整理交互。模型缺失允许安装后
  无需重启再试；运行时损坏或初始化失败会缓存失败并立即终止整项任务，不会对 150 张图片逐张重复初始化。
- 固定分发基线：微软官方 `Microsoft.ML.OnnxRuntime 1.20.1` x64 CPU DLL 及 providers 共享库
  已记录精确长度与 SHA-256；Rust 在动态加载前重新校验两者，并使用该官方 DLL 完成同一离线
  冒烟（1/1 通过，0.99 秒）。运行时与许可证仍不进入默认安装包。
- Windows 真实窗口冒烟：release 可执行文件正常创建主窗口；使用键盘从主导航进入采集箱，
  创建本地批次、通过系统文件选择器导入 1 张仓库测试图片并进入桌面整理台。工作台明确显示
  “智能分题仍在真实题图验证中”，同时保留“继续用顺序模板”；焦点环在“采集整理”“新建批次”
  “电脑批量选择”和“结束采集，开始整理”上可见。测试机 `AppliedDPI=96`，覆盖 Windows
  100% 系统缩放；另用只作用于测试进程的 WebView2 设备缩放参数完成 150% 内容缩放代理检查，
  主界面、批次列表和整理工作台无横向溢出，智能分题关闭态、顺序模板和素材操作仍清楚可达。
  该代理检查不冒充 Windows 150% 系统显示设置实机验收。
- Narrator 实机冒烟：在上述 150% 内容缩放代理窗口中启动 Windows Narrator，读屏焦点可识别
  主导航、批次标题/计数、智能分题关闭原因、顺序模板、图片裁剪/删除和正式入库状态；Tab 从
  “返回采集箱”跳过禁用的“手机扫码”到“电脑批量选择”，焦点框可见。由于真实样本证据门禁
  保持关闭，本轮无法在发布窗口中进入建议复核、应用和撤销，因此完整 Narrator 闭环仍待验收。
- 复核无障碍自动化：连续相同决定会先清空再更新 `aria-live`，避免 Narrator 忽略重复播报；
  每次接受/跳过包含当前位置，J/K/E/S 与输入框隔离均有测试；分类暴露 `aria-pressed`；
  影响确认打开后获得焦点，Esc 返回触发按钮并限制焦点循环；关闭复核后焦点返回
  “查看识别建议”。进度读屏区缩减为每张图片一条“已分析 N / 总数”，不会重复朗读整段说明。
- 真实题图证据入口：新增只绑定 `127.0.0.1`、以一次性随机令牌保护的离线可视化标注器。
  它自动发现 PNG/JPEG/WebP、副本不改写、草稿可恢复，并且只有每张图片至少有一个区域且
  匿名化/授权均明确确认后才生成 `manifest.json`。完整评测工具 38 个测试通过；实际浏览器
  完成拖动框选、题号锚点、版面/标签、授权、保存与安全关闭，390 px 窄屏无横向溢出且控制台
  无警告或错误。完整评测工具现有 41 个测试通过。该工具降低取证成本，但本轮 6 图开发集
  仍不计入 60/300 张发布准确率证据。
- 150 图开发机性能回归：专用本地实验台复用真实 `CaptureWorkspace`，挂载 150 个合成图片项
  用时 27.9 ms；往返 120 步滚动用时 862.0 ms，测量区间没有 ≥50 ms 长任务；预览缓存峰值和
  稳态均为 40。实际把首张缩略图拖到新卡区域后，未分配数从 150 变为 149、生成 1 张题卡，
  控制台无警告或错误。同时修复了旧缩略图被 40 张缓存淘汰后滚回不再加载的问题，并为同一
  可见项的并发请求去重。该结果是开发机回归证据，不代替 4 核 / 8 GB 参考机验收。
- 仍需人工完成下列真实题图、4 核 / 8 GB 性能、Windows 150% 系统缩放、减少动画模式和
  启用识别后的 Narrator 全闭环验收；证据门禁保持关闭。

## 全自动识题的发布阻断条件

- [ ] 60 张开发题图和 300 张盲测题图均来自真实拍照或相册来源。
- [ ] 题目起始召回率不低于 95%。
- [ ] 内容被裁断的区域低于 0.5%。
- [ ] 错误拆题率低于 3%。
- [ ] 4 核 / 8 GB Windows 参考机的单张暖启动 p95 低于 2 秒。
- [ ] 开始、分析、复核、应用和撤销期间没有网络请求。
- [ ] OCR、题答匹配、模型运行时和产品入口由同一个发布门禁审查，不能只因模型已安装而启用。

## 两种模式与失败状态

- [x] 智能切图明确说明“不识别文字、不匹配题答、不创建题卡”。
- [x] 全自动识题独立标注“未开放”，且没有可误触的运行或模型下载按钮。
- [x] 打开设置、采集批次或智能切图不会下载模型。
- [x] 智能切图失败不影响模板、拖拽、裁剪、笔记、标签和正式入库。
- [x] 取消、退出应用和丢弃批次都会停止工作，并清理私有明文临时目录。

## 容量、恢复与并发编辑

- [ ] 分别验证 1、50、150 张未分配图片。
- [ ] 任务在排队、运行和待复核阶段重启应用后可恢复。
- [x] 同一时间只有一个图片进入视觉切图引擎。
- [ ] 工作期间可以继续手工拖拽和裁剪，且不会被结果覆盖。
- [ ] 任务开始后新增的上传保持未分配，不会进入旧任务。
- [ ] 被移动、改角色、裁剪或删除的来源只会使对应建议过期，其他建议仍可复核。

## 真实题型矩阵

- [ ] 单题整页、多题同页、双栏、跨页续题。
- [ ] 只有题目、只有答案、题答数量不等、多图题目和多图答案。
- [ ] 公式、几何图、统计图、表格、手写批注、红笔订正。
- [ ] 模糊、透视、阴影、页面卷曲、低对比度和部分遮挡。
- [ ] 题号缺失、题号重复、答案编号缺失和编号不匹配。

## 复核与无障碍

- [ ] 默认先打开“需要检查”，为空时再打开“可快速确认”。
- [ ] 低可信和过期建议不能接受；批量接受只影响高可信建议。
- [x] J / K、Enter、E、S 均可用，且输入框不会被快捷键劫持。
- [x] 每次复核决定都有独立、原子化的屏幕阅读器状态播报；相同连续决定也会重新触发。
- [ ] 调整边界只保存提案，不提前创建裁剪资产。
- [x] 应用前明确列出来源图、题目切图、答案切图和保持不变项，并说明不会创建题卡。

## 原子应用、撤销与故障注入

- [x] 接受、编辑和跳过不会直接修改题卡；只有“放入素材牌库”会提交派生素材。
- [x] 写入 staging 前、写入 staging 后和数据库事务内分别注入故障，均为零部分应用。
- [x] 应用后只新增普通 crop 派生和未分配素材，不创建草稿、关联、Problem 或同步 outbox。
- [x] 撤销只删除仍保持生成状态的素材；任何后续移动、编辑、再次裁剪或正式入库都会返回冲突。
- [x] 源图始终保留；清理只删除没有其他引用的孤立资产。

## 备份、隐私与性能

- [x] schema v15 备份创建、验证与恢复覆盖排队任务、复核选择、操作账本和所引用的加密资产。
- [x] 当前 worker 不运行 OCR；数据库、日志、事件、绑定和 Vue 均不产生 OCR 文本或题号。
- [ ] 备份不包含 `optional-components`、`.staging`、明文图片、OCR 文本或绝对路径。
- [ ] 恢复后任务仍绑定原账户、学习档案和批次；外来账户行会被拒绝。
- [x] 150 张缩略图下滚动和拖拽无明显掉帧，主线程单次任务低于 50 ms（开发机回归）。
- [x] Windows 键盘、100% 系统缩放、150% 内容缩放代理和 Narrator 关闭态完成实机冒烟。
- [ ] Windows 150% 系统显示设置、减少动画模式和启用识别后的 Narrator
  复核/应用/撤销完成实机验收。
