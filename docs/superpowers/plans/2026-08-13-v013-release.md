# Mistake Trainer Next v0.1.3 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the current architecture and reliability remediation as the verified `v0.1.3` Windows release.

**Architecture:** Release from the existing `codex/bug-audit-v012` branch through a reviewed pull request. Merge into `main`, wait for the exact merge commit's push CI, then create an annotated `v0.1.3` tag so the repository's release workflow builds, smoke-tests, signs for Tauri updater verification, and uploads x64 and ARM64 artifacts into a draft GitHub Release. Verify all seven assets before publishing the draft.

**Tech Stack:** Git, GitHub CLI, GitHub Actions, pnpm 11, Vue/Vitest, Rust 1.97, Tauri 2, PowerShell, NSIS.

## Global Constraints

- Release version is exactly `0.1.3`; tag is exactly `v0.1.3`.
- `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, and `src-tauri/Cargo.lock` must agree.
- The release tag must be annotated, point to the current `origin/main`, and have a successful `CI` push run.
- Windows installers intentionally remain Authenticode-unsigned; updater artifacts remain Tauri-signed.
- The published Release must contain x64 and ARM64 installers, signatures, SHA-256 files, and `latest.json`.
- Do not expose private signing material; verify only the configured variable/secret names and generated signatures.
